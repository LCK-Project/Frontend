# 날짜 스트립 범위 선택 설계

작성일 2026-11-12. 대상 저장소는 `Frontend/`(브랜치 `feat/range-strip`)와 `Backend/`(브랜치 `feat/timeline-tournaments`)다.
이 문서가 두 저장소 공통의 유일한 설계 문서이며 Backend 쪽에는 사본을 두지 않는다.

## 1. 의도

그래프 아래 날짜 스트립은 지금 경기(Match) 노드를 날짜순 점으로 보여주고, 점을 누르면 그 경기로 포커스만 한다.
이 스트립을 "기간을 고르면 그래프가 그 기간으로 좁혀지는 조작부"로 바꾼다. 사용자는 답변을 받은 뒤
특정 대회나 특정 몇 달만 남겨 그래프를 읽고 싶어 한다.

## 2. 목표 · 비범위 · 피해야 할 결과

### 목표
- 스트립에서 세 가지 방법으로 기간을 고른다. 대회 띠 클릭, 월 칸 클릭 또는 드래그, from~to 월 입력.
- 고른 기간에 걸치지 않는 관계와, 그 때문에 관계를 모두 잃은 노드가 그래프에서 숨겨진다. 경기뿐 아니라
  소속, 코치, 챔피언 픽, 기사에서 뽑은 관계, 팬 댓글도 날짜를 따른다.
- 관계 필터 칩과 함께 적용된다(둘 다 만족하는 간선만 보인다).
- `전체` 버튼으로 선택을 풀고, `다시 배치` 버튼으로 남은 노드만 다시 배치한다.

### 비범위
- 기간에 맞춰 DB에서 그래프를 다시 불러오는 일. 이번에는 이미 받은 그래프(최대 100건) 안에서만 거른다.
- 오른쪽 답변 문장을 기간에 맞춰 바꾸는 일. 엔티티 목록, 필터 칩의 숫자, 근거 카드는 기간을 따라간다(5-5절).
- 스트립에 경기 외의 점(기사, 소속 변경)을 찍는 일. 점은 경기만 보여준다.
- 스테이지(정규, 플레이오프) 단위 띠와 패치 단위 띠.

### 피해야 할 결과
- 기간을 바꿀 때 노드 위치가 바뀌는 것. 무엇이 빠지고 남는지 비교할 수 없게 된다.
- 대회 띠 조회가 실패했다고 답변 전체가 실패하는 것.

## 3. 접근 방식

| 안 | 내용 | 판단 |
|---|---|---|
| A. 숨김으로 수정 (채택) | 노드와 간선을 지우지 않고 `hidden` 만 바꾼다. 위치는 그대로다 | 관계 필터 칩이 이미 이 방식이라 두 필터가 겹친다. 드래그 중에도 화면이 튀지 않는다 |
| B. 매번 새로 그리기 | 기간이 바뀔 때마다 남은 노드로 네트워크를 다시 만든다 | 위치가 전부 바뀌어 비교가 안 되고, 고정해 둔 노드와 상세 카드가 풀린다 |
| C. 기간마다 재조회 | 기간을 백엔드에 보내 그래프를 다시 받는다 | `/ask` 는 LLM 을 다섯 번 부른다. 그래프 전용 엔드포인트가 따로 필요해 이번 범위를 넘는다 |

A 의 약점은 기간을 많이 좁히면 남은 노드가 흩어져 보이는 것이다. 그래서 드래그를 놓을 때 남은 노드에 맞춰
카메라만 맞추고(`network.fit`), 원할 때만 `다시 배치` 로 물리 배치를 다시 돌린다.

범위 단위는 "대회 띠 + 월 칸" 을 함께 쓴다. 대회 띠는 되묻기의 대회 축과 같은 단위라 한 번에 고르기 좋고,
월 칸은 대회 경계와 무관한 미세 조정에 쓴다. 패치 단위는 패치별 경기 날짜가 데이터에 없어 제외했다.

## 4. 공유 계약: `/ask` 응답의 `timeline`

```json
{
  "timeline": {
    "tournaments": [
      {"name": "2025 LCK Cup", "start": "2025-01-15", "end": "2025-02-23"},
      {"name": "2025 LCK Rounds 1-2", "start": "2025-04-02", "end": "2025-06-01"}
    ]
  }
}
```

- `start`, `end` 는 그 대회에 속한 경기의 가장 이른 날짜와 가장 늦은 날짜(`YYYY-MM-DD`)다. `tournament.start_date`
  가 아니라 `match` 테이블의 실제 경기 날짜로 구한다. 점이 항상 띠 안에 들어오게 하기 위해서다.
- 응답 그래프의 날짜 있는 Match 노드 최소일~최대일과 겹치는 대회만, `start` 오름차순으로 담는다.
- 그래프에 날짜 있는 Match 가 없거나 MySQL 조회가 실패하면 `{"tournaments": []}` 다. 예외를 밖으로 내지 않는다.
- 프론트는 `timeline` 이 없거나 비어 있으면 대회 띠 줄만 비우고 나머지는 그대로 동작한다.

SQL:

```sql
SELECT t.tournament_name AS name, MIN(m.match_date) AS s, MAX(m.match_date) AS e
FROM `match` m JOIN tournament t ON t.tournament_id = m.tournament_id
WHERE m.match_date IS NOT NULL
GROUP BY t.tournament_id, t.tournament_name
HAVING s <= %s AND e >= %s
ORDER BY s
```

파라미터는 `(그래프 최대일 + " 23:59:59", 그래프 최소일)` 순서다.

### 4-2. `graph.links[].when`

간선마다 그 관계가 성립한 때를 구간 목록으로 싣는다.

```json
{"source": "…", "target": "…", "type": "MEMBER_OF", "evidence": null,
 "when": [["2025-04-01", "2025-07-23"], ["2025-07-23", "2025-09-10"]]}
```

- 구간은 `[시작일, 종료일]` 이고 둘 다 `YYYY-MM-DD`, 양 끝 포함이다. 종료일 `null` 은 열린 구간이다.
  하루짜리 사실은 시작일과 종료일이 같다. 목록은 중복 없이 시작일순이다.
- 날짜를 구할 수 없으면 `when` 은 `null` 이다.

| 관계 | 날짜의 출처 | 형태 |
|---|---|---|
| `MEMBER_OF`, `WORKED_FOR` | 관계의 `start_date` ~ `end_date` | 구간. 같은 두 노드 사이에 관계가 여러 개면 구간도 여러 개 |
| `PICKED_CHAMPION` 등 `game_key` 를 가진 관계 | 그 게임이 속한 경기의 `match_date` | 픽한 날마다 하루 구간 |
| 경기·팬 영상·팬 댓글·팬 의견 노드에 닿는 관계 | 그 노드의 날짜(`match_date`, `video_published_at`, `comment_published_at`, `created_at`) | 하루 구간 |
| 기사에서 뽑은 관계(클레임) | 기사 `published_at`, 없으면 기사 키에 박힌 날짜 | 기사마다 하루 구간 |
| 그 외 | 없음 | `null` |

같은 `(source, target, type)` 은 지금처럼 간선 하나로 접되 `when` 은 접기 전 것을 전부 모은다. 구조 간선과
클레임 간선이 같은 키로 겹치면 구조 간선의 `when` 만 쓴다. 소속 기간에 기사 발행일이 섞이면 기간 밖에서도
소속으로 보이기 때문이다.

## 5. 프론트 규칙

### 5-1. 축과 월 칸
- 축은 날짜 있는 Match 의 가장 이른 달부터 가장 늦은 달까지다. 달마다 같은 폭의 칸을 준다.
- 점의 x 는 그 달 칸 안에서 `(일 - 1) / 그 달의 일수` 비율 위치다.
- 대회 띠는 `start` 가 속한 달 칸의 왼쪽 끝부터 `end` 가 속한 달 칸의 오른쪽 끝까지이며, 축 밖은 잘라 낸다.
  축과 겹치지 않는 대회는 그리지 않는다.

### 5-2. 선택 상태
- 선택은 `state.range = null | { from: "YYYY-MM", to: "YYYY-MM" }` 하나다. 양끝 달을 포함한다.
- 월 칸 클릭은 그 달 하나, 드래그는 누른 달부터 현재 달까지(순서를 뒤집어 끌어도 된다), 대회 띠 클릭은
  띠가 걸친 첫 달부터 끝 달까지다. from~to 입력은 축 범위로 잘라 맞추고 from 이 to 보다 늦으면 서로 바꾼다.
- 이동 거리가 4px 미만이면 클릭으로 본다. 4px 는 손떨림을 드래그로 오인하지 않기 위한 값이다.
- 새 답변이 오면 선택은 `null` 로 돌아간다.

### 5-3. 무엇이 숨겨지는가 (순수 함수 `linkInRange`, `visibleSetForRange`)
- 선택이 `null` 이면 전부 보인다.
- 간선은 `when` 의 구간 중 하나라도 선택과 달 단위로 겹치면 보인다. 구간의 시작 달이 선택의 끝 달 이하이고
  구간의 끝 달이 선택의 시작 달 이상이면 겹친다. 열린 끝은 무한대로 본다.
- `when` 이 `null` 이거나 빈 목록인 간선은 항상 보인다. 날짜를 모르는 관계를 숨기면 기간을 고를 때마다
  근거 없이 사라지기 때문이다. 날짜 없는 경기도 같은 이유로 남는다.
- `when` 필드가 아예 없는 응답은 양끝 경기 노드의 날짜로 대신 판정한다.
- 노드는, 원래 간선이 하나 이상 있었는데 보이는 간선이 하나도 남지 않으면 숨긴다. `is_seed` 노드와
  원래 간선이 없던 노드는 숨기지 않는다.
- 관계 필터와의 결합(`visibleSet`): 필터가 `전체` 면 위 결과 그대로다. 그 외에는 "기간으로 보이는 간선" 과
  "그 묶음에 속한 간선" 의 교집합만 보이고, 노드는 그 간선들의 양끝만 보인다.

### 5-4. 화면 동작
- 드래그 중에는 숨김만 갱신하고 카메라는 그대로 둔다. 놓을 때와 클릭·입력으로 선택이 바뀔 때는 보이는
  노드에 맞춰 `network.fit` 을 애니메이션으로 실행한다.
- `다시 배치` 는 보이는 노드와 간선만 물리 계산에 넣어 안정화한 뒤 물리를 끄고 맞춘다.
- 선택 밖의 점은 흐리게 그린다. 점 클릭(경기 포커스와 상세 카드)은 지금처럼 동작한다.

### 5-5. 그래프 밖의 패널
- 엔티티 목록: 기간으로 숨겨진 노드는 목록에서도 뺀다. "더 보기" 는 남은 항목 기준으로 세고, 개수는
  기간을 고른 동안 `남은 수 / 전체 수` 로 적는다.
- 필터 칩의 숫자: 기간으로 보이는 간선만 센다. 0 이 된 칩은 누를 수 없게 하되 지금 켜진 칩은 막지 않는다.
- 근거 카드: 카드의 `(출발 이름, 관계, 도착 이름)` 과 짝인 간선이 기간으로 숨겨지면 카드도 숨긴다.
  짝 간선이 없는 카드는 항상 보인다. 전부 숨겨지면 "선택한 기간에 해당하는 관계가 없습니다" 를 보인다.
- 숨겨진 노드로 이동할 때(상세 카드의 이웃 버튼 등): 기간 때문에 숨겨진 노드면 기간 선택을 풀고,
  관계 필터 때문이면 필터만 푼다.

### 테스트 단언

`Backend/tests/test_timeline.py` (`_query` 를 monkeypatch)
- `test_span_from_dated_matches`: Match 날짜 `2025-04-20`, `2025-01-15` 와 날짜 없는 Match → `("2025-01-15", "2025-04-20")`.
- `test_span_none_without_dated_match`: Match 가 없거나 날짜가 없으면 `None`.
- `test_timeline_rows_to_bands`: 조회 행 `{"name": "2025 LCK Cup", "s": datetime(2025,1,15,17,0), "e": datetime(2025,2,23,15,0)}` → `{"name": "2025 LCK Cup", "start": "2025-01-15", "end": "2025-02-23"}`.
- `test_timeline_query_params`: `_query` 가 받은 파라미터가 `("2025-04-20 23:59:59", "2025-01-15")`.
- `test_timeline_empty_when_no_match`: `_query` 를 부르지 않고 `{"tournaments": []}`.
- `test_timeline_empty_on_db_error`: `_query` 가 예외를 던지면 `{"tournaments": []}`.

`Frontend/tests/graph-utils.test.js` 추가분
- `rangeStripLayout`: 픽스처(경기 2025-01-15 ~ 2025-09-06) 폭 924, 여백 12 → 월 9개, 칸 폭 100, 첫 칸 키 `2025-01`. `2025-01-15` 점의 x 는 `12 + 100 * 14 / 31`.
- 대회 띠: `2025-01-15 ~ 2025-02-23` → x 12, 폭 200. 축 밖(`2024-06-01 ~ 2024-08-01`) 대회는 빠진다. 축을 넘는 띠는 잘린다.
- `monthAtX`: x 가 축 왼쪽 밖이면 첫 달, 오른쪽 밖이면 끝 달, 칸 안이면 그 달.
- `normalizeRange`: 순서가 뒤집힌 입력을 바꾸고 축 범위로 자른다.
- `linkInRange`: 구간 겹침(달 단위, 양끝 포함), 열린 끝, 날짜 여러 개 중 하나, `when` 이 `null` 이면 항상 참, `when` 필드가 없으면 경기 날짜로 판정.
- `visibleSetForRange`: `null` 이면 전부. `2025-08 ~ 2025-09` 이면 1월 경기와 그 간선이 빠지고, 그 경기에만 이어졌던 노드가 빠지며, 시드와 원래 고립된 노드와 날짜 없는 경기는 남는다. 픽스처에서 봄에는 피넛·바루스가, 여름에는 제우스·오리아나가 보인다.
- `visibleSet`: 필터 `전체` + 기간은 `visibleSetForRange` 와 같다. 필터 `승패` + 기간은 두 조건을 모두 만족하는 간선만 남는다.

## 8. 함께 고친 것: 질문에 적힌 연도
- 질문에 연도가 있으면("2024 티원 전략") 그 해를 날짜 범위로 써서 그래프, 기사, 통계 검색에 적용한다
  (`Backend/app/clarify.py` 의 `question_date_range`). 전에는 되묻기에서 고른 범위만 적용돼, 연도를 직접 쓴
  질문은 전 기간으로 답했다. 연도가 여러 개면 가장 이른 해부터 가장 늦은 해까지다.
- 범위 밖 경기는 조회 쿼리 안에서 뺀다. 타입별 상한 20건을 건 뒤에 빼면 그 해 경기가 몇 개만 남기 때문이다.
- 서버의 날짜 필터는 경기뿐 아니라 `when` 이 범위와 겹치지 않는 간선과 그 사실도 뺀다.

- 숫자뿐인 키워드("2024")는 그래프 검색에서 뺀다. 경기 노드 이름이 날짜로 시작해 그 해의 아무 경기나
  핵심 노드로 잡히던 문제를 막는다.
- 핵심 노드 후보를 `Entity` 라벨 개체로 한정하고 이름·별칭 정확 일치로 찾는다. 규칙의 본문은
  `Backend/README.md` 의 "그래프의 핵심 노드(시드) 고르기" 절에 있다.

- 기사·그래프·통계 세 경로를 동시에 실행한다(`Backend/app/pipeline.py`). "2025 티원의 승리전략을 알려줘"
  실측에서 세 경로 구간이 36.8초에서 15.2초로 줄었다(전체 33.5초).
- 질문이 전략·밴픽·챔피언을 묻으면 경기를 최근 8개씩으로 줄이고 팀의 주력 픽 20쌍을 가져온다. 그 외에는
  경기 20개씩에 픽 8쌍이다. 값과 근거는 `Backend/app/search/neo4j_query.py` 의 `GRAPH_FOCUS` 에 있다.

## 9. 알려진 제약
- 브라우저 화면 조작은 사용자가 직접 확인했다. `다시 배치` 버튼은 자동 확인 수단이 없어 사람 확인에 의존한다.
- 질문의 범위는 연도만 인식한다. "2024 서머" 같은 대회 이름은 2024년 전체로 잡힌다.
